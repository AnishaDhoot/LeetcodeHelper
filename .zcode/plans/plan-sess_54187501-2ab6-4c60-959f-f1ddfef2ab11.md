## Remaining Tasks Implementation Plan

Two decisions confirmed: history fetched via **LeetCode GraphQL API** (background.js, using logged-in session cookies), and synced problems **register + ensure baseline TopicMastery** rows (score 0, no inflation).

---

### Task 1 — FastAPI endpoints (`backend/main.py`)

Append 5 POST endpoints that wire the already-imported (but unused) schemas to the already-implemented agent functions. Also add a `/health` endpoint for the footer status check.

1. `POST /approach/check` → `generate_approach_critique(...)` → `CheckApproachResponse`
2. `POST /hints/get` → `generate_hint(...)` → `GetHintResponse`
3. `POST /edge-cases/get` → `analyze_edge_cases(...)` → `GetEdgeCasesResponse`
4. `POST /help/ask` → `answer_custom_question(...)` → `AskHelpResponse`
5. `POST /sync/solved` → new handler (see Task 1b) → returns `{synced, topics, message}`
6. `GET /health` → `{status: "ok"}` (used by React footer to show real backend status)

Each new endpoint: parse `req`, call agent fn, return the typed response model. `CheckApproachResponse`/`GetEdgeCasesResponse` map the agent dict keys directly to the schema (they already align: `is_optimal`, `current_complexity`, `optimal_complexity`, `feedback`, `alternative_approach`; `edge_cases`, `constraints_critique`).

**Task 1b — `/sync/solved` handler logic (in `main.py`):**
- For each `SolvedProblemSyncSchema` in `req.problems`:
  - Upsert `Problem` (id = `problem_id`); set title/difficulty; join `topics` list → comma string. Use `https://leetcode.com/problems/{id}/` as URL.
- For each unique topic across all synced problems: ensure a `TopicMastery` row exists (create at score 0.0 / attempts 0 if missing). **Do not** modify existing rows or create attempts (no score inflation).
- Return `{"synced": <int>, "topics": <int>, "message": "..."}`.

No DB schema changes needed; reuses existing models.

### Task 2 — Background message routers (`extension/public/background.js`)

Add 6 new `if` blocks mirroring existing patterns (POST JSON body, parse, `sendResponse({success,data})`/`{success:false,error}`, `return true`). New actions:
1. `check_approach` → `POST /approach/check` (payload: problem_id, problem_title, code, language, constraints)
2. `get_hint` → `POST /hints/get`
3. `get_edge_cases` → `POST /edge-cases/get`
4. `ask_help` → `POST /help/ask`
5. `sync_solved` → `POST /sync/solved` (payload: `{problems}`)
6. `check_health` → `GET /health` (for the footer status)
7. `fetch_leetcode_history` → GraphQL fetch (see Task 2b). Runs in background (has cookie access via `host_permissions` for leetcode.com). Queries `userQuestionProgress` / `problemsetQuestionList` for solved questions; extracts `{problem_id, title, difficulty, topics}` per problem; returns to caller.

For Task 2b, implement `fetchSolvedProblems()` that calls `https://leetcode.com/graphql` with the `userQuestionSolved`/`userQuestionProgress` query (logged-in cookies sent automatically), then maps results into `SolvedProblemSyncSchema` shape. Topic info may be partial from GraphQL — pass through what's available, defaulting topic to the problem's primary tag or `"Arrays & Hashing"` fallback (matching backend default).

### Task 3 — LeetCode scraping + window bridge (`extension/src/main.jsx`)

Extend the existing content script so React can request on-demand context (currently the flow is one-way: verdict detected → analyze). Add helpers onto `window.dsaTutor` and a request/response bridge to `injected.js`:

- **`getCurrentConstraints()`**: scrape the constraints block from the problem description pane (the `<li>`s after the "Constraints:" heading) → string array.
- Attach `window.dsaTutor.getCode`, `.getLanguage`, `.getConstraints` for React to call on demand.
- Keep the existing `scrapeFailingTestcase` and `handleVerdictDetected` logic intact (auto-diagnosis on failure still works).
